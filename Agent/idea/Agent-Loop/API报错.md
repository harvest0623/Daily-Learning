# 错误分类
- 可重试：429（限流）、 529/503（服务过载）、 408（超时）、 ECONNESET（链接被重置）

- 不可重试：400（请求参数错误）、 401/403（认证失败）、 402（余额不足）

- 需要降级：连续出现多次529、流式链接反复断开。需要换策略


# 决策一：单次失败怎么重试
指数退避 + 随机抖动

1. 能不能固定时间重试？   --- 重试风暴

- 指数退避：第一次等500ms重试，第二次等1000ms重试，第三次等2000ms重试，以此类推，每次重试时间翻倍

- 随机抖动：每次重试时，随机添加0-100ms的延迟，避免所有重试同时到达服务器


- Retry-After：服务器返回的重试时间，单位秒


- 连续失败：模型降级，切换到其他模型


## 流式链接偶尔卡住
- TCP协议有一个半开状态（Half-Open），当用户网络发生抖动（切换WiFi、移动数据等），客户端的TCP链接可能会断开，而SSE维护的是一个HTTP长链接，浏览器层不知道TCP断开了，会一直挂起等待数据

- 解法：服务端心跳 + 客户端看门狗
    - 服务端心跳：服务端定期发送心跳包（SSE可以发送一些注释，不会触发客户端的反应）
    - 客户端看门狗：定时器，客户点记录最后一次收到数据的时间，如果超过阈值，就认为链接断开了，重新连接
