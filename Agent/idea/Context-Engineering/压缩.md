# 压缩
- 不管你的prompt管理做的有多好，Agent跑完50轮后，prompt的长度可能会变得很长，大概率会爆

# claudeCode 的三层处理
- 先试轻手段，不行再试重手段

1. Microcompact：
    - 不删消息，不该对话结构，只是把老旧的工具结果缩小
    比如：在第三轮循环时读一个文件 得到3000token的结果，但是等到第30轮的时候，这个3000token模型再也不需要用到它，那么就将这3000token替换成一句话，[Old tool result content cleared]，这样就可以节省token

2. Snip:
    - 直接砍掉老消息。从历史对话记录头部开始删除，被删的消息就永久丢失

3. Auto-compact：
    - 用LLM来生成摘要

## 什么时候触发这个压缩机制？
触发阈值 = effectiveContextWindow - 13k


## Auto-compact怎么压缩
1. 剥离图片：将上下文中的图片替换成 [image] 标记
2. Fork一个子Agent来生成摘要
3. 生成摘要：摘要本事是一个严格的 9段结构：
    - 用户意图
    - 技术概念
    - 文件改动
    - 错误修复
    - 问题解决
    - 用户消息
    - 待办任务
    - 当前工作
    - 下一步

4. 恢复关键文件：压缩后附加上最近读过的5个文件内容
5. 替换消息：
旧消息 ==> 新消息

[压缩边界标记]
[摘要]
[恢复的文件]
[最近对话]
