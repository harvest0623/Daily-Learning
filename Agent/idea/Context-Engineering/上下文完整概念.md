# context-engineering的五个维度
1. Offload(卸载)：      上下文太挤            把信息搬到上下文之外（文件，数据库）
2. Reduce（压缩）：     上下文太长             把信息压缩成更短的形式（摘要，向量化）
3. Retrieve（检索）：   需要的信息不在上文中     从外部源中检索相关信息（RAG，文件读取）
4. isolate（隔离）：  一个上下文装不下所有的事    拆成多个独立的上下文（Multi-Agent）
5. Cache（缓存）：      重复计算      复用已有的计算结果（KV Cache、 Prompt Cache）


## Offload(卸载)
上下文窗口是昂贵的，但是文件系统是廉价的

## Reduce（压缩）
1. Compaction(紧凑化)：不改变对话结构，把一些在循环对话中已经用的老工具替换成占位符”【old tool result cleared】“，或者将工具参数缩短

2. Summarization(摘要化)：用一段摘要替换整段对话，消息结构被破坏，取而代之的是一段LLM生成的文字总结，信息缺失更大，但是token回收多

## Retrieve（检索）
1. RAG(Retrieval-Augmented Generation)：把检索到的内容直接拼接到上下文中，或者用检索到的内容生成一个摘要再拼

## isolate（隔离）
多Agent系统中，每个Agent只处理自己擅长的任务，避免上下文过于庞大和复杂。

1. By communicating(消息传递)：主Agent给ziAgent发送消息，子Agent处理后返回结果，主Agent再整合结果。对于主Agent来说，上下文中只多出来的是给子Agent的消息和子Agent返回的结果，主Agent不需要知道子Agent的内部状态和处理细节。


2. By sharing context(上下文共享)：子Agent直接复制主Agent当前的上下文，在此基础上继续处理，  子Agent处理完后返回结果，主Agent再整合结果。

对于主Agent来说，上下文中只多出来的是子Agent返回的结果。

对子Agent来说，token消耗会更大，因为它需要复制主Agent的上下文。


- claudeCode 这两种隔离方式都支持，用户可以根据自己的需求选择合适的方式。


## Cache（缓存）
1. KV Cache（不受我们管控）
2. Prompt Cache（受我们管控）：把Prompt和对应的结果缓存起来，下一次遇到相同的Prompt就直接返回缓存结果，避免重复计算。
3. Context Collapse (上下文折叠)：把上下文中重复的内容折叠起来，减少token消耗。


# 5个维度的优先级
先 Offload > Cache > Reduce （先紧凑化，实在不行再摘要化）> isolate > Retrieve
