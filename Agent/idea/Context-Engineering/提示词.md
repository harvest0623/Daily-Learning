# Agent prompt   vs   chat prompt
1. chat prompt：追求高质量，问一个问题，得到一个高质量的回答
2. agent prompt：追求稳定性，模型可能连续跑50轮，每一轮都要作出正确的决策

    - Agent 中的 system prompt 是一套行为控制系统


# 问题一：Prompt 怎么分模块
普通的提示词：
"你是一个代码助手，帮用户完成编码任务，先读文件再修改。不要加没被要求的功能。执行危险命令要确认。输出要简洁，不要用......"

模块化的提示词：
const systemPrompt = [
    identitySection(),  // '你是xxx，负责xxx'
    systemRulesSection(),  // '你需要遵守的规则'
    taskGuidelinesSection(),  // 做事的方式：先读再写，不过度发挥
    riskGuidelinesSection(),  // 行动准则：危险命令要确认
    toolUseageGuide(),  // 工具指南：根据实际的工具列表来动态生成
    outputStyle(),  // 输出风格：简洁，不要用......
]

模块化的好处：
1. 独立修改：修改输出风格时，不会影响到身份和规则
2. 条件组装：某些section 可以根据不同的场景来选择性地加入或省略
3. 缓存友好：


# 问题二：什么该缓存？
system prompt 在静态和动态之间有一个分界

const systemPrompt = [
    // ---- 静态部分：全局可缓存，所有用户共享 ----
    identitySection(),        // "你是 XX，负责 YY"
    systemRulesSection(),     // 环境约束
    taskGuidelines(),         // 做事方式
    riskGuidelines(),         // 行动准则
    toolUsageGuide(tools),    // 工具指南
    outputStyle(),            // 输出风格

    // ======== 分界线 ========

    // ---- 动态部分：每会话不同 ----
    envInfo(cwd, gitStatus),  // 工作目录、Git 状态
    userConfig(claudeMd),     // 用户自定义规则
    languagePref(lang),       // 语言偏好
    memoryContext(memories),  // Memory 内容
]

# 问题三：用户怎么自定义Agent行为？
1. 越通用的配置，优先级越低
2. 低优先级的先加载，高优先级的后加载  --- 模型对prompt末尾的内容更敏感
