# Function Calling 机制
- 模型是不会自己调用函数的
    1. 我们在API调用时，给模型塞了一份工具菜单，是一组 JSON Schema, 描述了每个工具的名字、参数是什么格式，工具是干什么用的。
    2. 模型接收到这份菜单，再根据用户的问题，决定一要不要使用某个工具
    3. 如果要使用某个工具，模型就会生成一段符合JSON Schema的代码 --- 这就是所谓的函数调用
    4. 我们的代码解析这份JSON，再触发对应的工具函数
    5. 执行结果塞回到messages，再输入给模型，让模型生成回复


- 模型是怎么做到输出的 JSON 一定符合 JSON Schema 的格式？
    1. 训练
    2. 约束解码 --- 模型在测算当前的token时，将不合法的选项排除掉


# 工具越多，模型想要调用的工具就越不准
工具函数50+， 准确率 < 50%

1. 注意力稀释：工具越多，工具的描述在上下文中的权重就越小
2. 语义碰撞：不同的工具函数，描述的语义可能相似，导致模型无法准确判断要调用哪个工具
3. 预算挤压：工具越多，单次占用的上下文就越多，导致用户的消息和历史消息可用空间越少

ClaudeCode 的 Tool Search机制：
不是一上来就将所有的工具函数都展示给模型，而是把不常用的工具标记为 【延迟加载】，只在模型需要它的时候才看到它


# 模型会幻觉出不存在的参数
你让它读 src/utils.ts  它可能输出 src/helper/utils.ts

1. 用enum约束参数的可选值：
{
    "action": {
    "type": "string",
    "enum": ["read", "write", "delete"]
    }
}
2. 执行前校验
我们在执行工具函数前，先校验参数是否符合要求，如果不符合，就给模型返回一个建议信息
