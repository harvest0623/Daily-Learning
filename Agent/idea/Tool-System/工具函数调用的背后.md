# 工具系统设计的第一原则
模型生成的输入是不可信的

- 从 【模型表达意图】 到 【工具执行】 中间需要一条完整的处理管线
    1. 验证
    2. 校准
    3. 拦截
    4. 授权


# 一条管线的全貌
1. 验证模型输出的JSON类型
2. 业务逻辑的校准：语义层面校准
3. 拦截并补全：模型输出说要调用 read_file 函数，参数为 “src/index.ts”,这是相对路径，需要转换为绝对路径
4. 前置HOOK： 
    {
    "event": "PreToolUse",
    "command": "base /path/to/my-check.sh $TOOL_NAME $TOOL_INPUT"
    }
5. 权限检查：
    1. 规则匹配： 比如读取文件类的工具直接允许
    2. 分类器判断：需要一个轻量的分类器（LLM）来评估这个操作是否安全
    3. 交互式询问：规则和分类器都内办法决定，需要用户手动确认（弹框）
    
6. 真正的执行： tool.call()
    - 工具执行完得到的结果可能非常大，直接交给模型会导致上下文爆炸

    - claudeCode: 设置了 50k 字符的阈值，超过这个阈值的工具执行结果就被存放在磁盘上，而不是直接交给模型，给模型传输的是 内容摘要 + 文件路径
    
7. 后置HOOK： 
    工具执行完后做一些处理：
    1. 修改输出：敏感信息过滤
    2. 触发后续的动作：比如文件修改后自动lint
    3. 记录审计日志：追踪每次工具调用的详情
