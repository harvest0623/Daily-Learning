# LLM
1. 都是推理模型，只能基于自身已经训练好的语料库进行回应
2. 常见的LLM都是通用模型
3. 在一些私有领域，想要让LLM能接入这部分数据（企业的财务数据）
    - 全量微调 （效果更好，成本高）
    - 轻量微调 （效果差，成本低）
    - 构建本地的向量数据库 （效果好，成本低）

# context engineering
 - 致力于如何让LLM的上下文编排更合理
 - RAG: 构建本地的向量数据库，将用户问题和LLM的回答都存入本地向量数据库中，当用户发起新问题，先去向量数据库中做相似度查找，找出相似度最好的那几条数据，携带上传给LLM，这样就能有效的控制上下文的长度

# 实操RAG  （Retrieval-Augmented Generation 生成式检索增强）
1. ollama pull nomic-embed-text  安装一个专门用来生成向量的模型
2. pnpm i ollama    在项目中安装 ollama SDK
3. pnpm i vectra  安装一个node环境下的轻量级向量数据库
4. 初始化生成了一个本地数据库 （json文件）
5. 封装了 向量数据库 增加、删除、查找 的方法

# 向量相似度查找
1. 余弦距离
2. 欧氏距离
3. 点积值

# 结合到LLM中
收集项目文档 --》 通过embedding向量化得到向量 --》 存入向量数据库

用户提问 --》 通过embedding向量化得到向量 --》 在向量数据库中做相似度查找 --》 整合好的提示词 --》 LLM 输出
